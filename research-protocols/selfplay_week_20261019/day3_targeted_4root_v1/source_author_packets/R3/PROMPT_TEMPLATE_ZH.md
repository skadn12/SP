# 下一版本共同素材扩充提示词

本模板给对话扩充 Planner/Realizer 使用。它尚未执行，不是当前封存题目的补丁。执行前须将 ROOT_EXTENSION_REQUESTS.jsonl 中一个 root 请求及其完整 source 绑定到新的版本和调用预算。

你要延续一段已有对话，在自然的新进展中补充目前出题缺少的关系素材。输入为：`{root_extension_request}`、`{full_bound_source}`、`{inherited_route_policy}`、`{reserved_native_train_event_records}`、`{frozen_generation_budget}`。只按 AUTHOR_INPUT_ALLOWLIST.json 提供材料，不读取内部原缺额记录、Gold 数量、题目标签或配对素材溯源文件。缺少任何执行绑定时，只返回准备缺项，不生成。

遵循既有两条扩充路线，每条 3 场：路线 A 为 old_event_continuation（旧事件延续），路线 B 为 dataset_new_event（数据集新事件）。先完成并接受 A1、A2、A3，再依次完成并接受 B1、B2、B3，最终合为同一个累计 root。历史流程为 P+R01 开始；本轮未来版本从已绑定的完整封存前缀继续，不能丢掉已有 R02。每场都依赖先前接受的累计历史，前一场失败则停止本 root 后续依赖场。

source 路线 A/B 与出题实验组 A/B 是两个不同维度。共生成一份后续供两个出题组共用的 source 版本，不能分别给出题组补料。路线 B 保留“来自预先匹配并永久预留的未消耗 Train 数据集事件”的要求，绑定原始记录，不能改造数据集事实来凑联合关系。新人物仍按历史身份/说话人政策处理，本包不放开新增说话人；保持现有人物身份、角色、性别/指代一致。历史每场 12—16 turn 是溯源信息，具体下一轮调用和长度预算由新执行冻结明确。

首先读完整历史，提取与本次自然进展有关的人物、关系、当前有效计划、已完成事项和未决点，引用真实 turn_ref。然后将请求中的缺口对应到既有路线里合适的生活/工作话题，拟定六场计划。允许在新对话中发生新事实和达成新约定，不能改写历史事实或宣称历史早已有未写明的规则。不要求每场包含全部关系，更不能把对话写成六条现成考题答案。

条件/联合缺口的素材目标：在自然需要决策的情境中，由人物明确提出或确认一项有范围和方向的条件规则；在其他真实回合中分别报告案例的相关条件。至少有一个预期可问的关系需要合并两个以上非冗余前提，且涉及否定、条件或例外。缺任一必要前提组后，对行动/结果的合理判断应改变或变得无法确定；几条并列事实和生硬 if 清单不算完成。对不满足条件的情况，要有明确事实依据，不能把未提及当否定；不能把仅必要条件当充分条件。若新对话用一句话直接重述全部案例结论，后续不得把该案例标成跨 turn 必要推理。来源自然性优先，无法形成关系就保留缺额。

若请求还包括显式修订缺口：同一具体事项先有可定位的旧计划，再出现明确取消/替代和新有效计划。说明修改范围，保留计划、确认、执行完成的模态差异。仅补一个最新值、从未决定到首次决定、或解释原意，都不自动算明确替代链。

只按请求的上下文方向自然补充，人物自己约定的安排要归于本人；外部机构的回复只能作为新增事件明确报告。不能替历史未确认的服务、医疗结论、投资保证、个人同意或促销资格补出事实。不得读取 Solver 回答、错误卡、DEV/TEST 或其他实验组的题目。

输出六场对话及独立素材索引。每场保留真实边界、递增 turn_ref、人物与 text。索引列出新事实/规则的 turn_ref、适用对象、逻辑方向、否定范围、未决事项及旧状态承接。索引属于审核材料，不写进对话内容。不要输出题干、选项、Gold、预期模型错误或未经验证的模型弱点。

完整旧前缀逐字保留；输出进入新 source 版本。先由独立审核者对全文核查人物/状态一致性、自然性和实际关系覆盖；来源未接受不得出题。之后两个出题组使用同一接受来源、相同预定修复预算，并在新槽位与新版本下出题；当前封存缺额仍保持缺额。

记录实际调用、请求/实际 token、耗时、失败、修改与剩余缺额。不能用 Solver 分数选择扩充或题目。若另要证明这类素材反馈是否有用，应预先另设“有/无素材缺口反馈”的扩充对照；本模板的存在本身不能证明收益。
