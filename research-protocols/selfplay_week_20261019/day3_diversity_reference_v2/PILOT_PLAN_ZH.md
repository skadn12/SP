# 从数据集样例到本地生成的最小路径

这次先完成公开真实题例到可执行模板的映射，并在两个 Train root 上做素材可行性和完整样题试写。样题不是正式 A/B 入池产物，不读取本项目 DEV/TEST 来调整设计。参考数据集中的 DEV 样例仅为外部公开形式参考。

## 形式覆盖

多选优先验证：明示原因、时间/数量关系、条件联合结论、证据选择。人物绑定和修订终态作为已有形式保留参照。排序分别记录三种依据：原文叙述、明确时间、明确步骤；时间再分实际和计划，后者不冒充前者。插入、缺步和选择候选排列仅算回答形式变化。

实际存在多少种关系，由内容复核后的题决定；模板库里有标签不计已完成。特别是实际时间排序和必要依赖可能缺素材，要在缺额账本如实保留。

## 下一批验证设计

建议在当前20个公开 Train root 内按 source/root ID 的固定顺序选4个，生成前冻结题位与来源。每 root 目标3多选＋3排序，共24题位，作为新设计的内容和适配验证，不直接声称正式A/B效果。

- 多选12题位：原因、数量、条件联合、证据选择各3个计划位，Gold2–5各3位，生成前按 root/slot 循环登记；实现不了保留缺额。
- 排序12题位：原文复原、明确时间、明确步骤各4位；插入/缺步只作为辅助回答形式，不能冒充新的关系配额。实际时间与计划时间分别计数，不满足唯一六项时保留3–5项探索题或缺额，分别报告。
- 现有两个root的试写已经暴露于设计人员，后续这两个root仍仅作Train内容/诊断来源，不冒充未见最终评估。

先审核素材、逐项答案与目标操作，再冻结全部合格题、模型、排列、样本数和新格式适配。保留旧直接作答协议用于可兼容的六项题；新格式单列，不将不同项数的排序exact混成同一难度指标。当前只完成参考、模板和试写，不在本计划中声称24题已生成、Solver已运行或训练已开始。

## 完成的判断标准

必须看到新关系在真实对话中成功落地，并有完整 Gold 重建、缺额及题型覆盖账本。仅取得“至少两种场景计数组合”不再能证明排序关系多样性。若新关系缺素材，反馈给对话扩充的应是所需的自然事实结构，例如明确的回顾时间、可比较的时点或真实的步骤约束；扩充先做全文一致性审核，再重新出题。

最后再按冻结协议诊断 Solver。低正确率不当作题目质量或多样性的判据，训练收益留给共同评估和对照训练验证。
