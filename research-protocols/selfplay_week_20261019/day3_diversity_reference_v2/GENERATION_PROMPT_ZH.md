# 根据公开数据集形式出题：新设计分支提示词

本提示词用于新的多样性小试；不覆盖原187题的冻结规则。模板来源和真实原例见 research_mc、research_ordering、research_logic。借鉴题目的操作方式和证据组织，用本项目 Train 对话重新写题。

## 生成输入

你会收到完整的 Train 对话、source hash、可核对的 turn_ref、一个指定的 template_id，以及该模板的答案语义。首先阅读全文，列出实现这一模板必需的源素材。题干、选项、答案及证明必须使用同一 source 版本。

1. 写出本题要求模型执行的操作，例如计算间隔、解释明示原因、合并条件、选择必要证据、恢复步骤、按约定时点排列。
2. 找出最小充分证据及必要条件。与原文首次出现顺序相同不等于考查相同：要明确本题的答案依据是提及位置、事件时间还是程序约束。
3. 素材不够就返回 SHORTFALL，记录缺哪项必要关系以及后续对话扩充应自然补充什么。不能给原文补事实、强推原因、虚构规则或为满足六项而加入不确定事项。
4. 素材够才写完整题干和选项。题目必须明确对象、时间范围、实际/计划状态及回答方式。
5. 写出所有选项的判定与证据，或所有关键先后关系及其唯一性证明。提出一个可能的替代答案并解释它为何不成立；若不能排除，记 HOLD。

## 不同模板的答案合同

- **原因题**：问“对话明确说明的原因”，只接受被说话人明确说明或由必要证据严格推出的原因；相关事实不自动构成原因。
- **数量/时间题**：注明单位、参照时间、是否跨日；保存计算式。不同时间量可以作近邻干扰，但不能混合实际与计划来制造假难度。
- **条件结论题**：候选结论须被完整前提蕴含；必要条件和充分条件分开。反例须同时满足原前提。
- **证据选择题**：题干明确是“支持证据”“共同充分的证据”还是“不可缺少的证据”。无关项不等于假事实，不能套用原真假事实题的逐项反驳口径。
- **原文顺序题**：沿用明确的出现锚点；场景组合仅为证据结构字段，不算新的排序关系。
- **时间排序题**：明确比较实际已发生事件或计划时点，不能混用；给出时间值/严格先后关系，证明唯一顺序。并列、未知或不同时间轴不能被随意线性化。
- **步骤排序题**：限定为对话明确记录或约定的这一次操作步骤，不扩张成所有可能做法的必然顺序。若只靠报告位置排序就能得出答案，披露它与原文顺序的重合，不宣称程序依赖已被测到。
- **缺步/插入题**：固定其余步骤顺序，验证每个可选插入位置，唯一合法才入选。它是回答形式变化，不另算一种排序依据。

## 输出记录

返回 candidate_id、root_id、split=Train、source_path/hash、template_id、reference_dataset、primary_relation、answer_format、timeline_kind、question、options/items、gold、gold_semantics、逐项/逐对证据、必要性检查、alternative_answer_check、与现有模板的差异、source_material_status。

多选优先六项 Gold2–5；不能通过同义重复凑正确项。探索排序先用真实素材能支持的3–6项，须记录 arity，不能把四项题记成已完成旧六项配额。旧 Solver/训练适配器尚未支持的新格式先作为内容候选保留。

生成者给出的 Gold 只是候选。审核者使用完整 source 重建 Gold，记录实际审核身份与可见输入；共享文件系统上的代理复核不能描述为技术盲法或人类标注。

## 验收与反馈

先按内容正确性、目标操作是否实现及答案唯一性决定内容准入，再对全部准入题做固定 Solver 诊断。Solver 分数用于分析能力与后续反馈，不用于把答对的题删掉或挑出某个分数分布。A/B正式生产若采用这些新设计，两臂共享公开设计、来源与预算，仍只有B可使用合格弱点反馈。

覆盖统计分别报告 primary_relation、answer_format、证据结构与题干。模板名称不同、换词、展示排列或场景计数组合不同，不能自动增加 primary_relation 计数。
