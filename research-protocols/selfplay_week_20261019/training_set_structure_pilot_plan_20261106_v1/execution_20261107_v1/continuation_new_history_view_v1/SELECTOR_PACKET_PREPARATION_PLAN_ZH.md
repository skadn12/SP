# NEW 选择者构包与预检方案

状态：`DESIGN_ONLY_NOT_EXECUTED`。适用于控制端待处理的 OPP13。当前作者正在独立工作；本方案不读取作者文件、不读取目标、不创建角色包、不调用选择者。只有作者已经完成并冻结 slots 后才可执行依赖 slots 的步骤。原始合同、作者产物和既有审计保持不变。

## 阶段 0：预备材料

1. 重算 `CONTROLLER_PREPARATION_FREEZE_RECEIPT.json` 所列摘要、原合同、续跑规则和匿名 source/neutral 的字节哈希；任意不符即 HOLD。规则补充对历史 UNKNOWN 候选的频率排序改变了原合同第 (3) 条；仅以已披露的续跑补充执行，不声明原合同内容已变或仍是干净因果比较。
2. 控制端准备一次性隔离空间设计，使用不含机会、来源或分组标识的不可预测目录名。角色可见绝对路径只使用匿名路径组件，例如 `/tmp/q<random>/in/source.json`、`neutral.json`、`history.json`、`contract.txt`、`rules.txt`、`slots.json`、`packet.json` 和 `/tmp/q<random>/out/result.json`；实际路径需预先检查全部目录分量。控制端映射、原始路径和作者目录不投递。
3. 规划可验证的操作系统级访问边界：选择者只读匿名输入，只写专用输出位置，不能读取工作区、其他来源、作者文件、控制端映射或用户会话。匿名文件名、访问约定和提示词不能单独证明隔离；启动前须以选择者实际身份与相同执行环境做正向读写和受限路径的负向 canary 检验。若权限、挂载或沙箱无法实现并验证，HOLD，不声称实现隔离。

## 阶段 1：slots 已冻结后，控制端构包

1. 从机会原作者指定输出位置读取且仅仅读取 `NEW_SLOTS.json`、`SLOTS_FREEZE.json` 及必要的实际读取日志；不得遍历或读取其他作者内容。以严格 JSON 解析拒绝重复键、尾部非法文本或非预期类型，原始字节 SHA-256 与冻结记录逐字节一致，并绑定 source、机会、实际作者和冻结时间。冻结文件缺失、hash 不一致、已出现越界或提前题稿，隔离该机会，不修补、不重试。
2. 检查作者输出允许 0–3 个语义槽。若自然输出为 0/NO_SAFE_QA，按原合同终止该机会，不调用选择者。其余槽的 `slot_id` 为非空且唯一字符串；缺失、重复或类型错误即隔离。只投影原合同语义字段：`slot_id`、`natural_information_need`、`precise_query_scope`、`facts`（含 fact_id、proposition 及 evidence 的 turn_ref、quote、origin）、`semantic_answer`、`answer_program`、`required_relations`、`alternative_sufficient_paths`、`unresolved_relations`。这是目标语义答案，不是历史答案或题目选项。
3. 保持每个字段值、顺序、原文、关系、未决信息及交叉引用，不能删除 facts、关系、可影响选择的上下文或替代路径。仅剔除经确认是外层运行身份/路径的字段；若字段缺失、存在未识别但可能承载语义的内容、内层引用含身份导致无法在不改变语义或 ID 排序的情况下安全投递，HOLD，不猜测、不静默删除。若确需替换非语义标识，只有可证明一一映射、交叉引用一致且不改变原 slot_id 和排序时才允许；控制端保存完整映射及值级等价审计。任何选项、题型、答案标签或跨臂信息出现都按合同隔离。
4. 独立逐槽检查所有 `turn_ref` 的解析和 `quote` 的原文子串对应，固定使用有唯一解释的会话/回合映射；处理 global 和 session-local 编号时不能靠猜测回退，歧义即 HOLD。保持每槽原样与投影的语义等价核验；私有回执绑定原 slots、冻结文件、投影的字节 hash、大小、投影策略和映射。原始 slots 和作者路径不得进入选择者视图。
5. 把已验明的 source、neutral、历史视图、原 selector 合同、续跑补充和 slots 投影复制到匿名输入目录；每个副本的字节 hash 必须匹配相应冻结材料。将原始和副本的绑定保存在控制端。全量检查实际投递 JSON 的键、值、文件名、目录名、内容及引用，排除 root ID、机会 ID、group/arm、F/G、反馈身份、私有路径、其他来源和旧题选项/答案；不能仅靠正则。来源正文中的普通词汇必须原样保留，不用身份关键词过滤删改其含义。

## 阶段 2：选择者预检和单次执行

1. 先对专用输出目录采用独占创建（例如 `mkdir`，已存在即失败），权限只允许该次角色；结果文件路径必须尚不存在。执行器和选择者写文件时使用 `O_CREAT|O_EXCL`，同时防止符号链接跳转。不能覆盖已有输出或将失败输出修成通过。
2. 冻结匿名 `packet.json`：列出唯一允许读取的每个绝对路径和 SHA-256、唯一输出路径及输出 schema；不列原始路径、机会映射、分组或作者身份。控制端单独记录同一 packet 的匿名标识、字节 hash、与原机会/作者的绑定以及授权边界。检查最终绝对路径的每个分量和输入内容，不包含来源、机会或臂别标识。
3. 在选择者调用前以实际运行身份复核所有匿名副本字节、slot 投影及槽冻结绑定、严格 JSON、身份泄漏、允许路径、读写限制、目录独占、source turn count、引文映射以及角色包所用合同/规则一致性。source 需按实际可见的每段最多 30 turns 且不超过 12000 字符读取，neutral 单独读取；截断不算完整阅读。slots 必须先冻结，不得给选择者预览其他机会。
4. 单次选择者输出固定 schema，至少包括 `status`、`selected_slot_id`、每槽可行性及原因、准确来源引用、历史比较状态、已知/未知边界、操作/证据族映射及置信、替代充分路径、频数及跳过原因、规则和平局理由、输入哈希、实际读取范围和成题前限制。所有 slots 的 ID 按原始 Unicode code-point 字典序，不做 locale 排序或规范化。有效输入中没有可选槽时记 `NO_SAFE_QA`；schema 错、越界、hash 不符或不可追溯映射直接隔离，不重试。
5. 控制端完成合法输出和绑定检查后，仅向同一个原作者返回选中的原始 `slot_id`；不发送完整结果、比较、历史视图或其他槽。保留完整审计输出在控制端。独立审查发现问题时不能重选或重新生成。

## 统计与限制

本次历史视图不包含完整逐条语义比较：UNKNOWN 不得计作已确认新增或已知非重复。仅当所有未知候选能可靠且唯一映射到冻结操作/证据族时才按非互斥历史频数排序；否则整个同级回退 slot_id。频数仅是旧训练池标签参考，不证明历史新颖或未来题目结构。方案未冻结 selector 实际输入和执行环境，审查材料齐备之前不启动。
