## 每个冻结槽的判定与选择

1. 先按原方案检查来源证据、自然需求和范围；对当前合同要求可在选择前判断的允许题型可表达性也作预检，逐槽记录失败原因。不得补写事实、替作者生成目标或要求重提。此步骤不依赖历史状态。若有满足事实与需求条件的自然目标但均不能用允许题型表达，记 `FORM_UNSUPPORTED`；没有满足事实与需求条件的目标记 `NO_SAFE_QA`。
2. 在可行槽中，逐条比较选择器视图内相关记录的已知信息，记录比较对象、已证实的相同和不同、无法判断的维度及证据依据。事件、需求、范围及实际操作共同用于判断语义是否重复，证据关系辅助判断；不能仅因同一操作或词面相似就认定重复，也不能通过更换人名、表述或删节点认定新增。某个字段未知时，若其他可靠信息已经足以证明两者实质重复或不同，可以记录有依据的结论；否则该对比较为 UNKNOWN。选择器不得把 UNKNOWN 解释为不匹配。
3. 对每个可行槽只赋予一个状态：`KNOWN_DUPLICATE` 表示至少一个相关历史记录有充分依据证明实质重复；`REFERENCE_UNCOVERED` 表示视图内所有相关记录均有充分依据证明不重复，且不存在会影响该判断的未知记录或未知映射；否则为 `NOVELTY_UNKNOWN`。全字段未知的同源记录与槽的关系默认未知，不能假设不同。`REFERENCE_UNCOVERED` 仅指该冻结选择器参考集内可核验的覆盖，不是对未编码历史全集的证明，也不是质量审核或最终新增认定。
4. 从可行且非 `KNOWN_DUPLICATE` 的槽中选择：`REFERENCE_UNCOVERED` 优先于 `NOVELTY_UNKNOWN`；若前者为空，可选后者并保留未知状态。已确认重复的槽不参与选择。若所有可行槽已确认重复，记 `NO_SAFE_QA` 并记录各槽原因，不补槽、不重试。若基线、来源映射或隔离完整性不通过，记录基础设施/协议 HOLD，停止受影响调用，不伪装为 `NO_SAFE_QA`。
5. 同一状态等级内，仅使用经独立审计的 135 条合格训练记录作为频率分母。以审计固定的实际操作编码频数为第一关键字，证据关系族频数为第二关键字，均从低到高；字段为 UNKNOWN、未审定或无法可靠归类的历史行不计入相应字段的频数，需另报各字段已知/未知分母。附加历史和本轮草案、首稿不计入频率。若本等级任一候选的操作或关系族不能无歧义映射到冻结编码，或频数表的相关字段未完成审计，则本等级全部跳过频率排序并按 slot_id 决胜，不能把未映射视作零频。冻结编码及频数表须在作者调用前固定，禁止按本轮结果改变归类或排序。
6. 相同状态和频率时，使用合同预先冻结的 slot_id 顺序，取首个。选择记录须注明状态、已知重复或无法比较的原因、频率及其分母或跳过原因、平局规则。只将选中 slot_id 返回该机会作者；无替补、无重新选择，无法自然实现记 `FORM_UNSUPPORTED`。

## 统计与解释

每组按固定机会分母分别记录探索草案数、可行槽数、各历史状态槽数、选中状态、首稿数、`NO_SAFE_QA`、`FORM_UNSUPPORTED` 和协议/基础设施 HOLD。按 root、组分别报告，并保留反馈卡前置探索和选择后状态，避免将缺失视为零产出或把已知重复当成质量失败。

生成首稿并不等于质量 PASS 或历史新增。首稿冻结后按原方案统一盲审、结构复核、相对于各组同一冻结历史参考去重；后续还须检查保留的其他历史资料。分别报告首稿、质量 PASS、确认历史去重后的有效题、重复、历史新颖性仍未知及 HOLD 数。未知不能计入原方案 N 或 S 的确认下界，也不能单凭选择状态声称去模板化成功。可另报告将未知全部视为新增的敏感性上界，须明确只是界限，不能用于宣称满足原推进标准；缺失、未知和已证实重复分开。

## 与原方案的关系及生效条件

原方案规定优先历史未覆盖、同等可靠的非重复目标按合格训练覆盖排序，却没有规定未知状态的优先级。本补充明确“参考内可确认未覆盖优先，未知次之，已确认重复不选”；这会影响实际选择，属于预先披露的合同补充，不应冒充原合同已有规则。频率缺失时同级统一回退 slot_id，防止缺失被当作稀有。原方案中 8 roots、四组、反馈配置、32 机会、每机会最多一次首稿、固定基线、角色隔离和不补题规则不变。

现有 selector v3 草稿要求比较维度缺失时停止，且只允许四个结果键，不允许结果内逐槽比较表；v7 builder 也要求封存记录五字段齐全，并要求部分未知的附加记录整行 UNKNOWN。它们与本补充不同，不能直接宣称已符合。新版本须在调用前同步修改并冻结选择合同、角色输出/控制端逐槽审计格式、构建器及预检，使字段级 UNKNOWN、按源视图、状态和频率规则一致；逐槽语义判断须如实记录判断主体及证据，不能由机械字符串比较冒充语义审计。

启用前必须完成独立语义及隐私审核、所有视图和字段审计、来源与去重核对、合同和执行代码一致性检查、严格预检，绑定最终合同、输入、调度、记录格式和 hash；Stage A 复核与授权须对应最终执行清单。用户当前授权覆盖作者和选择者首稿流程；Solver、训练和导出仍须单独处理。若上述前提不满足，保留原因并停止相关调用。
