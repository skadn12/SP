# P2-2 concrete feedback transfer v1

The formal entry point calls the original `h4_qa_multiroot_k3_t08_probe_v1.generation.generate_root_qa`. Its optional hooks default to `None`; the original builders, intent canonicalizer, normalization, minimum admission, whole-batch repair and validator remain shared. No Planner, Realizer, original Miner default example, ordering method, seed or Memory change is made.

Common base `h4_r02_feedback_common_base_v1` freezes the six final P1 seed identities and documented eligibility, recounts eligible observations from exact historical request selectors, preserves inactive identity/stem/fingerprints, and versions a schema-only Miner format revision. P2-2 adds a separate binding envelope/validator and concrete Guided brief. Free sees only the original label, current full dialogue and eligible root observations; it cannot read a binding. Full provenance and mode/attempt trace remain sidecars.

The modes are `ORIGINAL_HOOK_DISABLED` (pass `hooks=None`), `LEGACY_COMMON_BASE` (offline common-base old append, intents-only, generic Writer), and `P2_2_CONCRETE_TRANSFER` (sole live mode here). See `P2_2_POLICY.md` and `schemas/`.

```bash
/root/miniconda3/bin/python -m scripts.current_method.restart_n5_spell.h4_r02_feedback_transfer_p2_2_v1.run --phase live --run /root/autodl-tmp/gxy-selfplay/restart-n5-runs/h4_r02_feedback_transfer_p2_2_acceptance_v1_live_1
/root/miniconda3/bin/python -m scripts.current_method.restart_n5_spell.h4_r02_feedback_transfer_p2_2_v1.run --phase report --run /root/autodl-tmp/gxy-selfplay/restart-n5-runs/h4_r02_feedback_transfer_p2_2_acceptance_v1_live_1
```

`prepare` is offline. It requires the initial source-code/P1 byte inventory and locally frozen service evidence/tokenizer. It runs the no-network tests, verifies the configured original service, checks all three real Miner prompts and freezes code/template/input/config SHA. The official provider catalogue verifies context capacity; the immutable tokenizer/chat template is additionally checked against every completed same-service P1 request with usage. Writer and repair requests are checked before reservation and current usage checked after durable completion. Full dialogue is never truncated.

`live` holds one nonblocking OS file lock for the entire run. Fixed root order is 198480, 122711, 197635. Planned logical calls are 21; cap 39 and cap 13 per root. Failed reservations count. Original HTTP retries are observed, never wrapped in outer retries. Every request checks code/input/config identity. Completed requests use only the original exact cache; known failed reservations replay their recorded failure without a send. An orphan reservation stops all further paid calls. A recorded live guardrail stop cannot silently restart this first acceptance. There is no force or resampling flag. An interrupted process without a guardrail failure may resume with this same `live` command only when all SHA and ledger checks pass.

`report` sends no requests and writes only new-run reporting artifacts. It reconstructs actual prompts from the original builders, retained raw primary data and exact compiled brief, and retains every returned candidate as accepted/rejected/replaced. It never changes Gold or admission. Full-content judgments are supplied by `Codex direct transcript review` under `reports/reviews/<root>.json`, with complete transcript SHA, six diagnostic fields, every SC/MS option, and ordering item/relation checks. Missing reviews remain incomplete, never fabricated PASS. `reports/readiness_assessment.json` stores the separately attributed overall quality judgment; local positive cases alone cannot make a run READY.

Only this first three-root acceptance is authorized here. P1 artifacts are read-only; report compares their complete initial file inventory. No Solver, six-root generation, training or Memory calls are provided by this entry point.
