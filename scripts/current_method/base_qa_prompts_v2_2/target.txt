ANSWER PROJECTION
Freeze answer_projection:{path:[...],expected_answer:<semantic value>}. path addresses the graph evaluator's actual symbolic_answer using object-key strings or nonnegative list indices; an empty path selects the whole result. The projected value must equal BOTH target.expected_answer and answer_projection.expected_answer exactly. Derive it from the executed graph rather than choosing a convenient answer field after seeing options. Invalid keys/indices, mismatched values, or a target answer unrelated to the symbolic result are blocking. Projection binds answer semantics; it does not establish that the source entails the symbolic inputs.

The current executable difficulty boundary is narrower than the generic path shape. For precedence_closure, only path:["order"] targeting the full supported order is accepted. For constraint_filter, only path:["solutions"] targeting the complete unique assignment is accepted. For guarded_transition, use path:["state","values",...query field keys]; work backward from the queried field and verify that each credited state update affects that field or a later guard that determines it. Updating an unrelated field must not raise this question's difficulty. The core also checks that cross-variable constraints actually restrict the solutions and that irrelevant/redundant typed inputs do not inflate the chain. A syntactically valid path is not sufficient: an unsupported projection or a chain irrelevant to the queried answer is HOLD. Preserve that limit instead of forcing the natural information need into a supported projection or changing the answer to obtain acceptance.
